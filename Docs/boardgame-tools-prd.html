01 / Overview

물건을 고르면, 그곳으로 가까이.

실물 보드게임 도구가 필요할 때, 하나의 앱에서 꺼내 쓴다. 같은 책상 위의 물건을 선택하고 가까이 들여다보며 조작한다. 다른 도구를 사용해도 이전 도구의 상태는 이어진다.

대상과 사용 상황

보드게임 중 주사위·시간 측정·토큰을 보조 도구로 사용하려는 iPhone 사용자. 기기 하나에서 도구를 번갈아 사용하는 상황을 MVP의 기본 흐름으로 삼는다.

제품 목표

  • 세 도구의 기본 기능을 빠르고 명확하게 사용할 수 있다.
  • 도구 전환으로 결과나 수량이 사라지거나 타이머가 멈추지 않는다.
  • 통일된 재질과 조명으로 오래 사용한 보드게임 책상의 분위기를 만든다.
도구는 그대로 있고,
카메라와 조작 대상만 바뀐다.

검증할 제품 가설: 세 도구를 같은 공간에서 다루는 경험이 기능별 화면을 오가는 방식보다 자연스럽고 즐거울 것이다. 사용성은 실제 프로토타입으로 검증한다.

02 / Scope

작게 만들되, 사용 흐름은 완결되게.

영역MVP에 포함MVP에서 제외
책상과 전환세 도구가 있는 3D 책상, 선택 시 클로즈업, 전환 중 상태 유지자유 카메라, 책상 꾸미기, 테마 선택
주사위6면체 1~10개 설정, 버튼·아이폰 흔들기로 굴리기, 결과 확인다양한 면수, 결과 기록·통계, 주사위별 잠금·재굴림
모래시계시간 설정, 시작, 리셋 후 시작 대기, 전환·세션 복귀 시 경과 반영, 종료 진동개별 모래알 물리 시뮬레이션, 다중 타이머, 일시정지
토큰1·5·10·20·50 단위별 개수 입력과 추가·제거, 동전 형태의 쌓임총액 자동 환전, 사용자 정의 단위, 플레이어별 자산 관리
저장과 연결동일 앱 실행 세션 내 도구 상태 유지앱 종료 후 복원, 로그인, 서버, 동기화, 멀티플레이

지원 환경은 iOS 26 이상이며 주사위는 일반 6면체, 최대 10개로 확정한다. 기본값은 주사위 2개, 모래시계 3분이다. 토큰은 기본 지급 없이 처음 사용할 때 단위별 추가 수량을 입력받는다. 남은 세부 정책은 08절에서 관리한다. 제외 항목은 이번 MVP 범위를 제한하기 위한 것이며, 향후 개발 약속을 의미하지 않는다.

03 / User journey

한 공간 안에서 이어지는 조작.

01. 책상 보기주사위·모래시계·토큰을 발견한다.
→
02. 도구 선택선택한 물건으로 카메라가 가까워진다.
→
03. 조작과 확인입력 UI와 결과를 함께 확인한다.
→
04. 다른 도구상태를 유지한 채 시점과 조작 대상을 바꾼다.

대표 사용 시나리오

  1. 주사위 개수를 설정하고 굴린 뒤 결과를 확인한다.
  2. 모래시계로 전환해 시간을 설정하고 시작한다.
  3. 토큰으로 전환해 원하는 단위의 개수를 입력하고 일부를 뺀다.
  4. 모래시계로 돌아오면 실제 경과만큼 줄어든 남은 시간이 보인다.
  5. 주사위로 돌아오면 이전 설정 개수와 마지막 결과가 유지되어 있다.
전환 UI 제안
클로즈업 화면에서도 다른 도구를 직접 선택할 수 있는 작은 전환 버튼을 제공한다. 책상으로 돌아가는 동작도 제공하되, 도구를 바꿀 때마다 책상 복귀를 강제하지 않는다. 구체적인 배치는 프로토타입에서 확인한다.
04 / Functional requirements

세 도구의 동작 계약.

공통 · 책상과 카메라

ID요구사항확인 기준
COM-01책상에서 세 도구를 식별하고 선택할 수 있다.각 도구를 탭하면 해당 도구의 클로즈업과 조작 UI가 표시된다.
COM-02선택 전환은 카메라와 조작 대상만 바꾼다.전환 전후 도구 데이터가 초기화되지 않는다.
COM-03카메라 이동 중 입력을 안전하게 처리한다.연속 탭으로 UI와 카메라의 선택 대상이 달라지지 않고, 의도하지 않은 중복 조작이 발생하지 않는다.

주사위 · 개수를 정하고 굴린다

ID요구사항확인 기준
DIC-01일반 6면체 주사위를 1~10개로 설정한다. 앱 시작 시 기본 2개다.0·음수·소수·11개 이상은 적용되지 않는다. 새 실행 시 2개로 시작한다.
DIC-02선택한 개수의 주사위를 버튼 또는 아이폰 흔들기로 굴리고 각각의 결과를 보여준다.표시된 주사위 수와 결과 수가 일치하고, 각 결과를 명확하게 읽을 수 있다.
DIC-03시각적 눈금과 결과 값이 일치한다.연출 종료 후 눈금과 표시 결과가 다르거나 판독할 수 없는 상태로 남지 않는다.
DIC-05굴리는 중에는 개수 변경과 재굴림 입력을 받지 않는다.버튼 연속 탭, 반복 흔들기, 두 입력의 동시 발생에도 한 번만 굴려지고 완료 후 다시 입력할 수 있다.
DIC-06흔들기는 주사위를 조작 대상으로 선택한 활성 화면에서만 동작한다.다른 도구 사용 중 흔들어도 주사위가 새로 굴려지지 않는다. 버튼은 항상 대체 조작으로 제공한다.
DIC-04도구 전환 후 설정 개수와 마지막 결과를 유지한다.다른 도구를 사용한 뒤 돌아와도 이전 결과를 확인할 수 있다.

구현 권고: 결과를 난수로 정하고 일치하는 3D 연출을 구성하는 방식을 우선 검토한다. 물리 시뮬레이션으로 결과를 결정하는 방식은 필수가 아니다. 굴리는 중 도구 전환 시 결과 확정 정책과 대기 중 개수 변경 시 기존 결과 처리는 미정이다.

모래시계 · 보지 않아도 시간은 흐른다

ID요구사항확인 기준
TIM-01사용자가 원하는 시간을 설정하고 시작한다. 앱 시작 시 기본 시간은 3분이며 시작 대기 상태다.유효한 양수 시간만 적용된다. 입력 단위와 최대 시간은 미정이다.
TIM-02다른 도구를 사용해도 카운트다운이 진행된다.복귀 시 남은 시간이 실제 경과 시간과 일치한다.
TIM-03설정한 시간으로 리셋할 수 있다.진행 중·종료 후 모두 설정 시간과 모래 양을 복원하고 시작 대기로 전환한다. 자동으로 재시작하지 않는다.
TIM-04모래의 위·아래 양과 낙하 효과로 진행률을 표현한다.진행률에 맞춰 위쪽 모래가 줄고 아래쪽에 쌓인다. 개별 모래알 구현은 요구하지 않는다.
TIM-06같은 세션으로 복귀하면 앱 이탈 중 경과 시간을 반영한다.시간이 남으면 실제 잔여 시간을, 만료되었으면 0과 종료 상태를 표시한다.
TIM-05시간 종료 상태를 식별할 수 있다.남은 시간이 0에서 멈추고 음수가 되지 않는다. 앱이 활성 상태이면 다른 도구를 사용하는 중에도 종료 진동을 한 번 제공한다.

토큰 · 단위별 동전을 쌓고 뺀다

ID요구사항확인 기준
TOK-011·5·10·20·50 단위의 동전형 토큰을 제공한다.각 단위를 숫자로 구분할 수 있다.
TOK-02단위별 원하는 개수를 입력하고 토큰을 가져온다.단위별 개수 입력 후 가져오기를 실행하면 현재 보유 수량에 입력 개수를 더한다. 예: 10 단위 3개 보유 중 7개 추가 → 10개 보유. 총액 자동 분해는 하지 않는다.
TOK-03가져온 토큰을 쌓인 형태로 표현하고 단위별로 제거한다.해당 단위의 현재 보유 수량까지만 제거할 수 있다. 예: 10개 중 4개 제거 후에는 최대 6개만 추가 제거 가능하다. 다른 단위는 변하지 않는다.
TOK-05새 실행 시 토큰을 자동 지급하지 않고 처음 사용할 때 단위별 추가 수량을 입력받는다.입력을 확정하기 전에는 보유 토큰이 없고, 가져오기를 실행하면 입력한 각 단위 수량만큼 생성된다.
TOK-04도구 전환 후 단위별 수량을 유지한다.돌아왔을 때 단위별 수량과 쌓인 표현이 유지된다.

구현 권고: 정해진 위치에 쌓고 추가·제거 시 짧은 움직임을 준다. 모든 토큰에 지속적인 물리 연산을 적용할 필요는 없다. 추가는 입력 개수만큼 누적하고, 제거는 단위별 현재 보유 수량을 한도로 적용한다. 구체적인 제거 UI와 수량 상한은 미정이다.

05 / State & lifecycle

보이는 화면과 살아 있는 상태를 분리한다.

대상세션 중 유지할 값전환 시 동작
주사위설정 개수, 마지막으로 확정된 각 결과선택 해제로 값이 초기화되지 않는다.
모래시계설정 시간, 실행/종료 상태, 종료 기준 시각다른 도구 선택과 관계없이 시간이 진행된다.
토큰단위별 개수, 쌓인 구성카메라가 멀어져도 수량이 유지된다.
화면현재 조작 대상과 카메라 위치새 선택에 맞춰 시점과 조작 UI를 바꾼다.

시간 계산 원칙

모래시계의 실제 시간은 렌더링 프레임이나 모래 애니메이션에 의존하지 않는다. 종료 기준 시각과 현재 시각의 차이로 남은 시간을 계산하고, 그 비율을 3D 모래 표현에 반영한다.

앱 종료와 앱 이탈의 구분

  • 확정: 앱 프로세스 종료 후 상태를 복원할 필요가 없다. 새 실행은 초기 상태로 시작해도 된다.
  • 확정: 앱 내부에서 도구를 바꾸는 것은 타이머 일시정지가 아니다.
  • 확정: 홈 화면 이동·화면 잠금 후 같은 세션으로 복귀하면 경과 시간을 반영한다. 이미 만료되었다면 0과 종료 상태를 표시한다.
  • 확정: 타이머 종료는 진동으로 알린다. 활성 앱 안에서 다른 도구를 보고 있어도 전달하며, 같은 실행 회차에 중복 진동하지 않는다.
  • 미정: 앱 비활성·잠금 중 종료 시 진동 전달 방식과 복귀 시 진동 처리. 경과 시간 반영과 별도로 검토하며, 백그라운드 진동을 보장한 것으로 간주하지 않는다. 별도 소리나 푸시 알림은 확정 범위에 포함하지 않는다.
기술 방향 · 확정
3D 엔진은 RealityKit을 사용한다. 입력과 결과 확인을 위한 일반 UI는 SwiftUI를 제안한다. 도구 데이터의 수명은 카메라나 개별 화면의 수명에 종속시키지 않는다. 구체적인 코드 구조는 구현 설계에서 정한다.
06 / Art direction

요소표현 방향가독성 원칙
책상짙은 월넛 목재, 은은한 나뭇결과 작은 사용 흔적배경 무늬가 도구와 UI를 방해하지 않는다.
주사위둥근 모서리, 아이보리 표면, 짙은 갈색 눈금마모가 눈금을 흐리게 하지 않는다.
모래시계오래된 황동 프레임, 투명 유리, 베이지색 모래유리 반사보다 내부 모래와 남은 시간의 식별을 우선한다.
토큰광택이 낮은 동전, 가장자리 마모, 크게 새긴 단위 숫자색조와 숫자를 함께 사용해 구분한다.
빛과 시점따뜻한 스탠드 조명 같은 빛, 부드러운 그림자, 비스듬한 상단 시점클로즈업에서도 결과와 숫자가 읽히는 각도를 유지한다.
조작 UI크림색 글자와 차분한 갈색 계열, 간결한 구성시간·개수·결과는 일반 UI로 명확하게 제공한다.

움직임

카메라는 같은 책상 안에서 이동한다는 연속감을 준다. 이동은 반복 사용을 방해하지 않게 짧게 설계한다. 토큰 추가·제거와 주사위 굴리기는 동작을 이해하는 데 필요한 만큼 표현한다. 구체적인 전환 시간은 프로토타입에서 결정한다.

07 / Acceptance

이 조건을 만족하면 MVP가 완성된다.

아래 검수 기준은 확정 범위에서 도출했다. iOS 26 이상과 주사위 최대 10개를 기준으로 확인하며, 대상 기기와 프레임 목표는 추후 합의한다.

검수시나리오통과 기준
A-01 · 주사위1개·기본 2개·최대 10개를 버튼과 아이폰 흔들기로 각각 굴리기각 결과가 1~6이고 요청 개수와 결과 수가 일치한다. 눈금과 표시 결과가 일치한다.
A-02 · 타이머60초 시작 후 다른 도구에서 20초 사용하고 복귀남은 시간이 약 40초이며, 전환 시점부터 다시 시작하지 않는다.
A-03 · 종료다른 도구 사용 중 설정 시간 만료활성 앱에서 종료 진동이 한 번 발생하고, 모래시계 복귀 시 0과 종료 상태가 표시된다. 복귀로 진동이 반복되지 않는다.
A-04 · 리셋실행 중·종료 후 리셋설정 시간과 모래 양이 복원되고 시작 대기가 된다. 시작을 누르기 전 시간이 줄지 않고 이전 카운트다운이 중복으로 진행되지 않는다.
A-05 · 토큰10 단위 3개에 7개 추가, 4개 제거 후 7개 제거 시도, 도구 왕복추가 후 10개, 제거 후 6개다. 보유량을 초과한 제거는 적용되지 않으며 6개가 유지된다. 다른 단위 수량이 변하지 않는다.
A-06 · 입력빈 입력, 음수, 소수, 한도 초과 입력 시도허용하지 않는 값이 상태에 적용되지 않고 수정 방법을 알 수 있다.
A-07 · 전환세 도구를 연속해서 선택카메라·조작 UI의 대상이 일치하며 마지막 유효한 선택으로 안정된다.
A-08 · 종료 경계앱 프로세스를 종료하고 새로 실행주사위 2개, 모래시계 3분·시작 대기, 토큰 미지급 상태로 시작한다. 토큰 첫 사용 시 단위별 추가 수량을 입력받는다.

추가 검수 시나리오

  • A-09 · 중복 입력: 굴리는 중 버튼 연타·개수 변경·반복 흔들기를 시도해도 진행 중인 굴림이 한 번만 완료된다.
  • A-10 · 흔들기 범위: 주사위 선택 상태에서는 흔들기로 굴려지고, 모래시계·토큰 선택 상태에서는 굴려지지 않는다. 실제 iPhone에서 확인한다.
  • A-11 · 세션 복귀: 60초 시작 후 앱 이탈 20초 뒤 같은 세션 복귀 시 약 40초가 남는다. 60초를 넘겨 복귀하면 0과 종료 상태다.
  • A-12 · 종료 진동: 실제 iPhone의 진동 사용 가능 환경에서 활성 앱의 타이머 종료를 확인한다. 다른 도구 사용 중에도 한 번 전달되고, 리셋 후 새로 시작한 회차에는 다시 전달된다.

품질 원칙

  • 주요 값은 3D 시각 효과만으로 전달하지 않는다. 눈금·남은 시간·토큰 수량을 읽을 수 있어야 한다.
  • 단위 구분은 색상에만 의존하지 않는다. 조작 요소에 접근성 이름을 제공한다.
  • 카메라 애니메이션은 동작 줄이기 설정을 고려한다.
  • 투명 유리·그림자·다수 토큰을 함께 보여주는 상황에서 실제 기기 성능을 확인한다.
  • 표시 중인 모든 물건에 지속적인 물리 시뮬레이션을 적용하는 것을 목표로 삼지 않는다.
08 / Decisions

확정한 정책과 남은 결정.

확정 · v0.2 사용자 추가 결정에 따라 지원 환경, 조작 방식, 초기 상태를 확정했다.

항목확정 정책
지원 환경최소 지원 버전 iOS 26. RealityKit을 사용한다.
주사위일반 6면체, 1~10개, 초기 2개. 버튼 또는 아이폰 흔들기로 굴린다. 굴리는 중 개수 변경과 재굴림 입력은 받지 않는다.
모래시계초기 3분·시작 대기. 리셋하면 설정 시간으로 복원 후 시작 대기. 도구 전환 중 계속 진행하고, 같은 세션 복귀 시 앱 이탈 시간을 반영한다. 종료는 진동으로 알린다.
토큰처음 사용할 때 단위별 추가 수량을 입력한다. 가져오기는 현재 수량에 입력 개수만큼 누적 추가한다. 제거는 단위별 현재 보유 수량까지만 허용한다.
저장앱 종료 후 복원하지 않는다.

남은 미정 사항

항목결정할 내용
지원 기기·방향구체적인 지원 기기와 화면 방향. 흔들기와 진동은 실제 iPhone 검수가 필요하다.
주사위 전환·개수 변경굴리는 중 다른 도구로 전환할 때 결과 확정 정책과 대기 중 개수 변경 시 마지막 결과 처리.
시간 입력입력 단위와 최대 시간, 실행 중 설정 시간 변경 허용 여부.
비활성 상태의 종료 진동잠금·백그라운드에서 시간이 만료될 때 전달 방식과 복귀 시 진동 여부. 경과 시간 반영 정책은 확정이며 진동 전달 정책만 미정이다.
토큰 표시와 한도최대 추가·보유 수량, 여러 스택으로 나누는 방식, 단위별 제거 UI의 구체적인 구성.
성능 기준아직 미정. 대상 기기, 목표 프레임 수와 토큰 최대 수량 조건을 추후 정한다.
09 / Delivery approach

흐름을 검증하고, 재질을 완성한다.

  1. 공간과 전환 검증. 단순 도형으로 책상·세 도구·카메라 이동·조작 UI를 구성하고 실제 기기에서 확인한다.
  2. 기능과 상태 검증. 주사위 결과, 타이머 경과, 토큰 수량을 연결하고 도구 왕복 시나리오를 통과시킨다.
  3. 빈티지 표현 적용. 목재·아이보리·황동의 재질과 조명을 통일하고, 모래 진행률과 토큰 쌓임을 다듬는다.
  4. MVP 검수. 입력 경계, 빠른 전환, 시간 종료, 기기 성능과 가독성을 확인한다.

기술 선택 근거

사용자 결정에 따라 RealityKit을 채택한다. Apple은 WWDC25에서 SceneKit의 soft deprecation과 신규 앱에 대한 RealityKit 권고를 설명했다. RealityKit으로 가상 3D 장면을 제공할 수 있으며, 이 프로젝트는 AR 카메라를 사용하는 경험을 요구하지 않는다. Apple · Bring your SceneKit project to RealityKit

완료 정의
확정된 세 도구를 하나의 책상에서 사용할 수 있고, 전환해도 결과·진행 시간·수량이 이어진다. 미정 정책을 확정한 뒤 검수 기준을 충족하며, 추가 기능 없이 일관된 빈티지 표현을 제공한다.

# U6 / Step 06 · 동전형 토큰 추가와 제거

**목표:** 다섯 단위의 수량을 정확하게 누적·제거하고 쌓임으로 표현한다.
**요구사항:** TOK-01~05, A-05·06·08.
**선행:** U2·U3. P-06 한도·표현·제거 UI, P-07 입력·일괄 처리 정책을 확정한다.

## 작업

- [ ] 1·5·10·20·50 단위와 단위별 수량을 숫자로 표시한다.
- [ ] 새 세션은 보유량 0이며 첫 토큰 사용 시 단위별 추가 입력을 제공한다.
- [ ] 가져오기는 현재 수량에 입력 개수만큼 누적한다.
- [ ] 모든 입력과 합산 후 수량을 검증하고, 한 필드 오류로 일부 단위만 추가되는 상황을 방지한다.
- [ ] 제거 단위와 개수를 입력받고 최신 보유량 이내에서만 적용한다.
- [ ] 잘못된 제거는 일부 차감 없이 거부하고 다른 단위도 유지한다.
- [ ] 고정 위치 스택과 짧은 추가·제거 연출을 연결한다.
- [ ] Step 02에서 만든 단위별 각인 동전과 공유 메시·재질을 재사용한다. 0개일 때 선택 영역만 유지하고, 보유량을 암시하는 표본 스택은 표시하지 않는다.
- [ ] 처음 입력 취소·전체 0·상한 도달 시 UI를 P-07에 맞게 처리한다.

- 수정: `BoardMate/Features/Tokens/TokenEntityFactory.swift` — Step 02의 실제 동전에 스택 배치·추가·제거 연출을 연결

## 접근 방식

수량의 원본은 모델이며 엔티티 생성·삭제 완료가 다시 수량을 바꾸지 않는다. 연속 요청은 연출 중인 수량이 아니라 최신 모델 수량을 기준으로 검증한다. 재질·메시를 공유하고 동전마다 지속 물리 연산을 사용하지 않는다. 총액을 단위별 수량으로 자동 환전하지 않는다.

## 테스트 시나리오

1. 첫 진입 전 보유량 0 → 입력 확정 후 입력 수량만 생성된다.
2. 10 단위 3개에서 7개 추가 → 10개, 4개 제거 → 6개, 7개 제거 시도 → 거부·6개 유지.
3. 10 단위 제거 → 1·5·20·50 단위의 수량은 변하지 않는다.
4. 음수·소수·빈 값·상한 초과 중 한 필드가 오류 → 전 단위 수량이 그대로다.
5. 현재 보유량이 한도에 가까울 때 추가 → 합산한 값까지 검증한다.
6. 제거 연타 → 각각 최신 보유량 기준으로 처리하며 음수가 되지 않는다.
7. 다른 도구 왕복 → 수량과 스택이 일치한다.
8. 입력 취소→재진입, 전체 0 입력, 보유량 0에서 제거 → 확정한 P-07 정책과 일치한다.

**완료 기준:** 수량 단위·UI 테스트 통과, 전 단위 누적·거부 시 불변 확인, 확정 최대 수량에서 스택 수와 숫자가 일치한다.

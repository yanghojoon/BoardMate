# U2 / Step 02 · 실제 3D 도구와 책상·카메라

**목표:** 처음부터 실제 사용할 RealityKit 주사위·모래시계·토큰과 기본 빈티지 재질을 만들고, 같은 책상 안에서 선택·클로즈업을 검증한다.
**요구사항:** COM-01·02·03, A-07, PRD 03·09절.
**선행:** U1. P-01의 검수용 iPhone을 정한다.

## 작업

- [ ] RealityKit 비 AR 장면에 월넛 책상과 실제 도구 엔티티를 배치한다. 전체 보기와 클로즈업 모두에서 사용할 형태로 제작한다.
- [ ] 주사위: 모서리가 둥근 아이보리 D6와 여섯 면의 눈금, 눈금별 로컬 축·최종 회전 매핑을 준비한다.
- [ ] 모래시계: 황동 프레임·투명 유리·위/아래 모래·낙하 효과의 분리된 하위 엔티티를 준비한다. 진행률 0·50·100%를 주입해 표현을 검증한다.
- [ ] 토큰: 두께와 테두리가 있는 저광택 동전과 1·5·10·20·50 각인을 준비한다. 초기 보유량 0일 때도 선택할 수 있는 받침 또는 선택 영역을 둔다. 제작 검수용 표본을 실제 지급 수량으로 사용하지 않는다.
- [ ] 세 도구의 EntityFactory에 메시·재질 생성과 하위 엔티티 구성을 모으고, 피벗·축·스케일·선택 충돌 영역을 고정한다.
- [ ] 기본 메시 조합과 로컬 자산 중 제작 경로를 정하고 자산 목록에 출처·제작 방식·사용 권한을 기록한다. 모델 로딩 실패용 대체 도형은 예외 경로로만 둔다.
- [ ] 따뜻한 조명·부드러운 그림자를 구성하고 투명 유리·눈금·각인이 실제 iPhone에서 보이는지 확인한다.
- [ ] RealityView의 가상 카메라, 도구 엔티티 선택, 프로그램에 의한 시점 전환을 실제 iOS에서 검증한다.
- [ ] 이 경로가 요구 동작을 충족하지 않으면 RealityKit ARView의 비 AR 경로를 검토하고 선택 이유를 기록한다.
- [ ] 책상 전체와 세 도구 클로즈업의 고정 시점을 구성한다.
- [ ] 도구 탭·직접 도구 전환·책상 복귀를 제공한다.
- [ ] 선택 상태를 하나로 유지하고 전환 요청 번호로 늦은 이동 완료를 무효화한다.
- [ ] 이동 중 실행 입력을 차단하며 새로운 도구 선택은 마지막 유효 요청으로 재지정한다.
- [ ] P-08 전환 시간 후보를 확인하고 동작 줄이기 모드의 즉시/최소 이동 경로를 검증한다.

## 접근 방식

도구 전환은 같은 장면의 시점을 바꾸는 방식으로 구성한다. 도구별 EntityFactory는 실제 제품에서 계속 사용하고 Step 04~06에서 동작을 추가한다. 이 단계에서는 정적인 초기 상태와 표현 검수용 값으로 형태를 확인하며, 난수·타이머·수량 규칙을 임시로 중복 구현하지 않는다. 도구별 수치는 Step 03 이후 세션 모델에 연결한다. 카메라나 엔티티를 데이터 저장소로 쓰지 않는다.

기본 빈티지 재질과 식별에 필요한 디테일은 이 단계의 완료 조건이다. 미세한 흠집이나 장식 텍스처는 이후 조정할 수 있지만, Step 07을 실제 모델의 최초 제작 단계로 미루지 않는다. 실제 형상으로 카메라 프레이밍과 선택 영역을 확정하고 기본 성능을 측정한다.

## 테스트 시나리오

1. 각 도구 탭 → 해당 시점과 이름이 있는 조작 영역이 일치한다.
2. 주사위→타이머→토큰을 빠르게 선택 → 마지막 토큰 선택으로 안정된다.
3. 앞선 카메라 완료 이벤트가 늦게 도착 → 현재 선택과 패널을 덮지 않는다.
4. 이동 중 임시 실행 이벤트를 주입 → 실행 요청이 차단된다. 실제 버튼·흔들기의 통합 검수는 해당 기능이 구현되는 Step 04 및 Step 08에서 수행한다.
5. 클로즈업에서 다른 도구 또는 책상으로 이동 → 중간 책상 복귀를 강제하지 않는다.
6. 동작 줄이기 사용 → 전환 후 선택과 UI가 일치하며 긴 이동이 없다.
7. 실제 주사위 여섯 면·모래 진행률 0/50/100%·다섯 토큰 단위 표본 → 눈금·모래·각인이 클로즈업에서 식별된다.
8. 토큰 0개 → 토큰 선택 영역이 유지되고 표본 동전이 보유량으로 표시되지 않는다.

**완료 기준:** 실제 사용할 세 도구의 형태·기본 재질·엔티티 구성이 준비되고, 시뮬레이터 UI 검증과 실제 iPhone에서 식별·선택·짧은 전환을 확인한다. 검증 결과·렌더러 선택·초기 성능 측정은 `Docs/QA/Tabletop-Scene.md`에 기록한다. 이 단계는 도구 기능의 구현 완료를 의미하지 않는다.
